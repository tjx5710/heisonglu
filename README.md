# 产线闭环仿真 · 从 Python 图纸到可交互 HTML

一次完整的「读懂图纸 → 移植成网页 → 调优闭环」练习：把一条会持续漂移的虚拟产线，
做成双击就能跑的单文件交互端，并在上面把控制策略调到又快又稳。

- 单文件 HTML，**零依赖**、无任何网络请求，双击即开
- 随机序列与 Python 参考实现**逐位一致**（复刻 CPython 的 MT19937），同一组参数得到完全相同的数字
- A 组（刀具磨损 ×1.1）调优：**第 22 批收敛 / 保持期 CPK 1.24 → 第 14 批 / 1.63**

---

## 这条产线在仿什么

一台数控磨床连续加工轴类零件，目标外径 20.000 mm、公差 ±0.020 mm。加工中存在三类扰动：
刀具磨损（每件缓慢增大）、温度漂移（随机游走）、测量噪声。每 10 件一批，每批结束后用
最近 30 件的测量数据算均值偏移 `e` 与过程能力指数 `CPK`。

| 常量 | 值 | 含义 |
|---|---|---|
| `TARGET` / `TOL` | 20.000 / ±0.020 mm | 目标尺寸与公差半宽 |
| `BATCH_SIZE` / `MAX_BATCHES` | 10 件 / 40 批 | 每批件数与赛程上限 |
| `INITIAL_WEAR` | 0.012 mm | 开线时刀具已有磨损（第 1 批 e 就从 +0.014 起步） |
| `WEAR_PER_PART` | (0.0001, 0.0004) mm/件 | 刀具磨损，每批约 +0.0025 mm |
| `TEMP_PER_PART` | (-0.00005, 0.00015) mm/件 | 温度随机游走，每批约 +0.0005 mm |
| `NOISE_SIGMA` | 0.0035 mm | 单件测量噪声 |
| `RATE_LIMIT` | ±0.006 mm/批 | 速率限制：单步补偿的执行上限（静默截断） |
| `GUARDRAIL` | ±0.020 mm/步 | 安全护栏：超过则**整条作废**、转人工 |
| `COMP_CAP` | ±0.150 mm | 累计补偿行程上限 |
| `ACT_DELAY` | 1 批 | 执行延迟：本批决定的补偿下一批才生效 |
| `STATS_WINDOW` / `CPK_TARGET` / `CONSEC_PASS` | 30 件 / 1.33 / 3 批 | 统计与收敛判据 |
| `HOLD_BATCHES` | 8 批 | 收敛后继续跑的「保持赛」 |

A 组剧本把 `WEAR_PER_PART` 换成 `(0.00011, 0.00044)`，即磨损快 10%。

## 闭环怎么转

```
测量（10 件/批）→ 统计（最近 30 件的 e 与 CPK）→ 决策（补偿 = −e × 增益，带死区）
      → 执行（先撞护栏，再被 ±0.006 截断，下一批才生效）→ 再测量
```

三个设计要点，都是这套仿真「反直觉」的地方：

- **速率限制 + 30 件滑动窗口**决定了补偿的极限速度：一次满额补偿 0.006，只能把窗口均值拉低
  0.006 ÷ 3 = 0.002/批，所以从 +0.014 降回 0 至少要 7 批，谁都快不了。
- **执行延迟**让大增益适得其反：等效滞后约 2.5 批，增益超过 1 之后收敛批次不再变短，
  只有保持期 CPK 在掉。
- **护栏与速率限制的失效方式不同**：护栏是「整条作废」，速率限制才是「截断」。
  所以策略应当自己把请求夹到 ±0.006 —— 执行结果不变，却永远咬不到护栏。

收敛判定 = CPK 连续 3 批 ≥ 1.33；收敛后不停机，继续跑 8 批保持赛，用保持期 CPK 均值论英雄。
成绩 = 收敛批次（越小越好）+ 保持期 CPK 均值（越大越好）+ 全程超差件数（越少越好）。

## 成果

同一随机种子（8）下，只改策略参数：

| 页面 | 策略 | 收敛批次 | 保持期 CPK | 全程超差 |
|---|---|---|---|---|
| `我的产线.html` | 标准产线 · 死区 0.002 / 增益 0.5 | 第 21 批 | 1.32 | 0 件 |
| `A组_1出问题.html` | A 组 · 死区 0.002 / 增益 0.5（基线） | 第 22 批 | 1.24 | 0 件 |
| `A组_2调优后.html` | A 组 · 死区 0.001 / 增益 1.0（药方） | **第 14 批** | **1.63** | 0 件 |

调优不只是种子 8 的运气：A 组基线在 20 个种子里只有 **15/20** 收敛（与档案卡所述一致），
新参数是 **20/20**，平均 10.5 批收敛、平均保持期 1.53。

稳态误差公式也验证了这条策略的合理性：`|e|∞ ≈ 每批漂移 ÷ 增益`，
0.0033 ÷ 1.0 = 0.0033，而实测保持期 `|e|` = 0.0034。

## 怎么运行

**交互端**：双击任意 `.html` 即可（Chrome / Edge 均可，无需服务器）。
页面内可调节死区、增益、随机种子，点「自动运行闭环」逐批推进；改参数会自动重置赛程。

**Python 图纸**（可选，用于对照基准）：

```bash
python agent_loop.py        # 打印标准产线的逐批日志与最终成绩
```

自检：默认参数（死区 0.002 / 增益 0.5 / 种子 8）应在**第 21 批**收敛，
保持期 CPK 均值 ≈ 1.32，全程超差 0 件。

## 移植的正确性怎么保证

任务书允许「HTML 随机序列与 Python 不同」，但本项目没有走这条捷径：页面里完整实现了
CPython `random.Random` 的 MT19937 + `init_by_array` 播种，以及 `random()` / `uniform()` /
`gauss()`（极坐标法 + 第二值缓存）的位级行为。因此同一组参数下，HTML 与 Python 得到**逐件相同**的
测量值，而不是「数值接近」。

验证方式：把页面里的 `sim-core` 脚本抽出来，用 Node 跑 8 组场景（标准线 / A / B / C 组，
含不同增益与种子），与 Python 逐批比对 `e`、`σ`、`CPK`、窗口超差、补偿量，以及前 40 件测量值
（10 位小数）——全部一致；20 个种子的收敛率也与档案卡记录的基准完全吻合。
